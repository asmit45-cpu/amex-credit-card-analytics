# AmEx-Style Credit Card Analytics: Fraud Risk, Churn & Spend Behaviour

End-to-end analytics project on a simulated credit-card portfolio, built with **SQL, Python (pandas, scikit-learn), Excel and an interactive dashboard**. It answers three business questions: where does value come from, which transactions are fraud, and which customers are about to leave.

> **Note on data:** the dataset is **synthetic** (generated by the scripts in `python/`) so that fraud and churn have a known ground truth to validate against. This is a portfolio project and is not affiliated with American Express.

**Live dashboard:** https://asmit45-cpu.github.io/amex-credit-card-analytics/AmEx_Dashboard.html

## Business Problem
A card issuer with 1,500 customers (4 card tiers, 8 spend categories, 24 months) needs to:
1. **Understand the portfolio:** which card tiers and categories drive value?
2. **Catch fraud:** flag suspicious transactions without blocking genuine customers.
3. **Predict churn early:** find customers whose usage is falling so retention can act.

## Dataset (synthetic)
| Table | Rows | Description |
|---|---|---|
| `dim_customer` | 1,500 | card type, city, income, age, tenure, credit limit |
| `fact_monthly_spend` | 288,000 | customer x month x category spend |
| `fact_transactions` | 60,000 | individual transactions with fraud label (1.17% fraud) |

## Methodology
**1. SQL (`sql/analysis_queries.sql`)**: business-question queries using joins, CTEs and window functions (segmentation, YoY growth, seasonality, customer momentum, fraud by category, RFM-style VIP segments).

**2. Fraud model (`python/06_fraud_detection_model.py`)**: Random Forest with `class_weight='balanced'` for the 1.17% class imbalance. Evaluated with precision, recall, F1, ROC-AUC and PR-AUC (not accuracy). Decision threshold tuned to ~75% recall.

**3. Churn model (`python/07_churn_prediction_model.py`)**: engineered features (6-month spend momentum, trend slope, volatility, dormant months); Random Forest outputs a risk-ranked register of all 1,500 customers.

**4. Excel dashboard (`outputs/AmEx_Analytics_Dashboard.xlsx`)**: Executive Summary, Portfolio, Fraud and Churn sheets; summary sheets are formula-driven (SUMIF / COUNTIF / INDEX-MATCH), not hardcoded.

**5. Interactive dashboard (`AmEx_Dashboard.html`)**: 3 pages (Portfolio, Fraud, Churn Risk).

## Key Findings
| Area | Finding |
|---|---|
| Portfolio | Centurion cardholders are ~6% of customers but average about 5x the lifetime spend of a Green cardholder |
| Spend mix | Travel and Online Shopping together drive over 40% of total spend |
| Fraud | Fraud rate is similar across merchant categories (about 1.0-1.4%, Healthcare slightly highest), so category alone is a weak signal; fraud is concentrated between 1-4 AM and in high-amount, far-from-home transactions |
| Fraud model | At the tuned threshold the model caught 131 of 175 test-set frauds (~Rs 81.7 lakh), with 0 genuine transactions flagged |
| Churn | 180 customers (12%) flagged high-risk, about Rs 2.09 crore of annualised spend at risk |

## Recommendations
- Add step-up verification for late-night (1-4 AM), high-amount and far-from-home transactions, since these are the strongest fraud signals in the model.
- Run a retention programme for the 180 flagged customers, prioritising Platinum and Centurion tiers. Retaining even 30% protects an estimated Rs 1.25 lakh of annual revenue (illustrative, ~2% take rate).

## Limitations
- The data is synthetic and the fraud/churn signal is cleaner than real life, so both models show near-perfect test scores (ROC-AUC 1.0). On real data they would need re-validation.
- Next steps: cost-sensitive threshold (weigh false positives and false negatives by rupee cost), tenure-aware churn features, and a Power BI version of the dashboard (`powerbi/POWERBI_BUILD_GUIDE.md` has the data model and DAX).
